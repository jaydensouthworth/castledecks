# Release 66 candidate

This source-tested candidate adds a returning-player Crownroad Hall and explicit entry into the existing local-save chooser. Native acceptance is pending. [Release 65](https://github.com/jaydensouthworth/castledecks/commit/e70ec2953760f74b94ca50f2c886d111fd20c7d6) is the known-good rollback.

## Changes

- Preview validated same-origin local Crownroad checkpoints from the illustrated Hall: active profile and provenance, actual saved frontier/region artwork, timestamp, and the exact preparation/opening/result state.
- Keep the reader read-only. It does not write or remove saves, acquire save locks, restore a game, start combat or send network requests. Four adventures, original artwork and the first-visit/no-JavaScript experience remain available.
- Explain newer, corrupt, recovered or unavailable storage. Bound profile names as text and use fixed authored artwork mappings. Refresh on storage/lifecycle changes and clear stale text or art when the saved state becomes unavailable.
- Open the existing chooser through the explicit battle?open=local-saves link without creating a blank slot during setup. Ordinary battle entry retains normal autosave behavior; Continue, New, import and Session only remain explicit decisions.
- Suppress the irrelevant pointer-transparent flag reminder only during contract trials. Real flag state and Pause information remain unchanged, and ordinary game reminders remain available before and after a trial.

No save schema, account service or game backend is introduced. Temporary-session protections and earned-progress boundaries remain intact.
