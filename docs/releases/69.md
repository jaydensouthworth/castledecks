# Release 69 candidate

This candidate improves tactical card discovery and finite-levy readability, and integrates dormant account frontend modules. Native acceptance is pending. [Release 68](https://github.com/jaydensouthworth/castledecks/commit/11ad1267b1a223b544520b0c374e801228735088) remains the accepted rollback.

## Changes

Twelve unit contracts gain distinct engine-grounded purpose subtitles, capabilities and tradeoffs. The catalog retains generic roles and adds six grouped jobs: flag carriers, fast flag runners, tower garrison, healing/poison purge, long-range siege and flying support. Discover shortcuts and current-deck job counts lead to the existing filtered catalog. Counts describe equipped contracts, not deployed troops or strength scores, and roles may overlap.

Catalog, Collection and Build quick facts expose actual gold and reserve cost per squad. Build inspection and two-card Compare reuse existing lazy atlas portraits. Unknown/custom records do not inherit capabilities from a copied name or portrait. Ice Demon describes its defensive frost identity and current fire-resistance-based melee without changing balance.

In real finite-levy encounters, the paused Army entry reports readiness, dispatch and slot state and opens Muster directly. Only the explicit Call action commits troops. Counted nearby pennants replace overlapping per-unit lettering while small markers identify actual temporary troops. Teams stay separate, controller ownership is checked, and dead/hidden/destroyed/garrisoned units do not acquire visible counts. Labels account for status glyphs and marker geometry, with connectors beneath them and an explicit omitted-label state for mathematically impossible tiny viewports. Ordinary non-levy drawing order is retained.

Dormant account UI, client, model, codec and journal modules are included with feature-off defaults and zero default visible/network footprint. No Go service, backend or provider configuration is included. Saves never migrate or upload automatically. Enabled native layout, real Google/provider/proxy operation and production account activation are unverified and disabled.

All 37 engine modules and all artwork are byte-identical to release 68. Ordinary troop costs, simulation and earned progression are unchanged.

## Verification and limits

The exact final canonical source passed 1,981 combined engine, UI and recruitment checks with zero failures, cancellations or skips. The portable mirror adds the eight existing server/packaging checks for 1,989 total, preserving all 177 runtime files byte-for-byte. GitHub CI repeats the portable gate and then builds the actual Docker/Nginx image, checking syntax, real HTTP routes, exact container-served source bytes, module MIME, cache headers and missing-file responses.

Focused coverage includes 65 account, 23 Muster, 10 card-discovery and 16 prior Return regressions. Levy layout checks include minimized negative controls, a 240-pixel case, four zoom scales, mixed teams/heights and a 300-layout permutation sweep; an independent 10,000-layout sweep found no supported-viewport collisions, clipped visible labels, omissions or count/state errors. These checks do not replace native rendering acceptance.

Native candidate acceptance must still cover narrow portrait and short landscape layouts, job-to-card trial Return, painted Build/Compare portraits, deck job navigation, direct Muster readiness/slot transitions, crowded pennant/status readability and the disabled account footprint. Physical-device touch/lifecycle behavior, extended stability, broad balance and exact original Flash runtime equivalence remain unverified. Browser-local saves stay tied to the website address; export a backup before changing the address or clearing site data. Full live-host asset byte equality remains unverified. Repository, CI-container and native browser checks are separate evidence.
