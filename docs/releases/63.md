# Release 63 candidate

This narrow presentation correction was initially published with native rechecks pending. The exact release 63 subsequently passed both reported marker cases and the Army-receipt check, and is the known-good rollback for release 64.

## Changes

- Keep company banner ground poles and troop-line anchors fixed while moving only the decorative cloth clear of existing Battery objective labels. The frame-local layout flips the cloth left when possible, otherwise raises it a bounded amount.
- Preserve original placement when there is no camera/objective context. Placement uses CSS-pixel camera geometry without DOM measurements, input listeners, timers, simulation writes or device-pixel-ratio-dependent offsets.
- Clear a stale Army queued-after-Resume receipt when the observed battle tick changes. A genuinely paused receipt remains visible, and the existing survival explanation returns afterward. No gold, reserve, queue or recruitment state changes.

Every engine file is byte-for-byte unchanged from release 62. No gameplay, company membership, real ground positions, attack ranges, costs, stats, save schema or input controls change.

## Verification and limits

The exact source passed 1,656 combined engine, UI and recruitment checks with zero failures or skips. The public mirror preserves all 158 runtime files byte-for-byte and retains eight portable server/packaging checks, producing a full gate of 1,664 checks.

Fourteen new marker regressions cover 9,576 banner geometries across held groups, four terrains, two seeds, three threats and short-landscape/portrait views without company/objective-label intersections. A real UI regression covers clearing the stale Army receipt after resumed simulation while preserving the paused receipt and ordinary resource accounting.

Native release-62 observations motivating this correction were Frontline Center overlapping Battery I at 740 by 320 CSS pixels with safe insets, and a unified Forward banner overlapping Battery labels in a 390 by 844 whole-field portrait view. The controlled layout checks clear those cases while retaining the real ground anchors. Subsequent native testing of fresh runtime 63 confirmed both intersections were corrected, poles stayed fixed and controls remained clear. A real four-Grunt deployment also cleared the old receipt with 1,180 gold, 66 reserve and an empty queue, without a refund.

This is not a general obstacle solver for all HUD elements. The bounded raised cloth can still approach the HUD in extreme crowded layouts. Automated geometry coverage does not establish native layout, long-session behavior or physical touch acceptance.

Release 61's accepted native Battery-clearance/Army-copy checks and the earlier native Battery victory/retry remain established. Physical Android/touch, orientation/lifecycle behavior, extended stability, native portable save-file round trips, broad balance and exact original Flash runtime equivalence remain unverified.
