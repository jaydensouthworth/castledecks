# Release 67 candidate

This source-tested candidate adds optional finite levy defense, a bounded local profiler and an explicitly synthetic disposable test field. Native acceptance is pending. [Release 66](https://github.com/jaydensouthworth/castledecks/commit/91b7e4ceaf70cf38322c677482b8c6f8b5e17bc8) is the accepted rollback.

## Changes

- Add a fifth optional Skirmish doctrine with four manually called five-unit levy waves. Each has three ordinary Grunts, one Archer and one Priest. Twenty total temporary tickets and ten auxiliary slots are accounted separately from paid contracts and caps. Corpses, ownership, cooldown and dispatch timing retain their real effects; company orders apply by role.
- Disclose four enemy stages at 0/45/100/160 simulation seconds. Destroying the hostile keep withdraws undispatched reserves; deployed enemies and home-flag recovery still matter. Whole-tick resolution prioritizes actual hero, home-keep and flag loss. Immediate feedback and results use the recorded loss conditions; ordinary CTF remains unchanged.
- Offer an off-by-default, memory-only 30-second profiler. Separate animation callback intervals, render-submission intervals, render CPU and tick CPU. Count real living/draw-eligible/viewport identities. Label handler-entry-to-next-render-submission latency precisely; it does not measure OS/touch/GPU presentation. Pauses/backgrounding consume the fixed elapsed deadline and break measurement chains. Source changes explicitly invalidate samples, including between-frame trial entry/return. Nothing is sent, saved or automatically exported.
- Add a clearly labelled synthetic Testing field with 44 or 48 ordinary rank-2 troops, real auxiliary ownership and derived caps. It starts paused at staging tick 201; setup does not simulate actor steps. Staged supplies are not natural waves or paid purchases. Resume runs normal combat; zero reserve and guarded actions prevent replenishment. The disposable scene ends after 120 simulation seconds or a terminal condition without settlement. Reset/Return restore the exact origin. Save/import/export/profile routes and stale asynchronous handlers remain guarded; reports identify controlled-fixture mode.

No account service, game backend, earned-progress schema or original-game assets are introduced. All 35 pre-existing engine modules remain byte-identical to release 66; two optional levy modules are added with explicitly reviewed fingerprint guards.

## Verification and limits

The exact final canonical source passed 1,867 combined engine, UI and recruitment checks, with zero failures or skips. The portable mirror retains eight server/packaging checks, producing a full 1,875-check gate. Its 167 runtime files are preserved byte-for-byte from the frozen source.

Automated coverage includes finite tickets and dispatch accounting, ownership/corpses/caps, complete-tick defeat precedence and immutable reasons, legacy doctrine parity, profiler interval separation and lifecycle invalidation, synthetic staging counts and guards, deadline/termination, and exact temporary-origin restoration. Scripted natural-play policies and factory counts are not human win rates, mobile balance results or native performance evidence.

Release 66 passed native first-visit/returning Hall, checkpoint semantics, explicit chooser cancellation/confirmation, cross-tab refresh, narrow zoom layout and the trial reminder correction. Earlier accepted actual recruitment costs, healing, damage, compact controls and company-marker checks remain established.

GitHub CI repeats the full portable gate from pinned dependencies, then builds the actual Docker/Nginx image and checks syntax, HTTP routes, exact container-served source bytes, module MIME, cache headers and missing-file behavior.

Known candidate issue: returning from the synthetic field restores the origin state, but the Pause battle title can still display the synthetic-field label. A follow-on correction and native recheck are required before acceptance.

Candidate 67 still requires native levy outcomes/readability, actual controlled-load counts, profiler lifecycle/input behavior and responsive layouts. A 44/48-troop capacity or staged count does not establish that many simultaneous natural-play actors, acceptable frame pacing or guaranteed FPS. Physical Android/touch, long-session stability, native portable save-file round trips, broad balance and exact original Flash runtime equivalence remain unverified.

Browser-local saves stay tied to the website address. Export a backup before changing the address or clearing site data. Full live-host asset byte equality remains unverified; exact repository/CI-container checks and native browser acceptance are separate evidence.
