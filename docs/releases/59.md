# Release 59

This release adds a spatial Wayfarer route board, clearer battlefield orders and a bounded allied siege role to release 54.

## Changes

- Inspect six connected Wayfarer fields on a branching board. A charter still consists of four battles; taking an available road prepares its field without automatically starting combat or replaying rewards.
- Select fixed Rear, Center or Forward Rally lines through live controls or the Army workspace. The chosen landmark stays independent of hero and camera movement; the Rally shortcut releases and reapplies it.
- Let recruited allied trebuchets attack a distant hostile keep or occupied hostile tower when normal distant-troop selection finds nothing. Troop targets retain priority, with ordinary range, windup, scatter, damage, cost and reserve rules.
- Reject friendly or neutral building targets and recheck ownership through release and impact. Enemy siege AI, Gorath, save formats and economy values are unchanged.
- Repair shared route, Army and Build navigation at short landscape sizes. Keep compact Profile/Save status text readable and Back targets at least 44 CSS pixels high.

The player homepage, About page, browser-local saves and Docker/Nginx packaging remain available. No backend or account service was added.

## Verification

The accepted game source passed 1,482 combined engine, UI and recruitment checks with zero failures or skips. The final build/status-only revision adds one metadata-consistency regression and passes 17 focused checks. Its 155 runtime files are imported byte-for-byte. This public repository retains the established portable canvas imports and pinned historical-reader fixtures, and adds eight server/packaging checks for a complete total of 1,491 including the metadata regression.

The release gate validates syntax, markup, asset references and publication hygiene, then runs all portable tests. GitHub CI installs the pinned dependency lockfile and separately builds the real production container, validates Nginx and checks HTTP routes, exact served source bytes, module MIME, cache headers and missing-file responses.

Cloud Chromium acceptance covered the six-field board, locked inspection, explicit earned branch selection/start, reset focus/cancellation, native Rally selection and shortcut, paid siege recruitment with rendered siege engines, battlefield firing, shared navigation and compact status text at portrait and short-landscape CSS sizes, including safe-inset simulations. These checks used disposable or explicitly labelled QA profiles.

Controlled regressions and accelerated actual-engine policies verified the allied building-target fallback and ordinary economy accounting. They are not human win rates. A short native siege smoke test showed ordinary recruitment and visible engines; it did not establish native siege damage attribution or siege-to-victory play.

Physical Android/touch, orientation and lifecycle behavior, extended browser stability, a native portable save-file round trip and broad balance remain unverified. CSS viewport/inset testing is not physical-device acceptance. Existing native HUD coverage warnings remain a limit; the game is not claimed to have zero battlefield occlusion. The native 300-card scale fixture and exact original Flash runtime equivalence also remain unverified.

Checkpoints preserve preparation or settled results rather than a live battlefield. Export saves before changing website address or clearing site data.
