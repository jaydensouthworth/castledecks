# Release 75 candidate

This candidate improves portrait Build cards and short-landscape header clearance. Native acceptance is pending. [Accepted release 74](https://github.com/jaydensouthworth/castledecks/commit/877c974d6cc98d241b01187156dc21d3b4500f04) remains the rollback. Source revision: `9f7e11609b9e864b81f47fbc3e5d3907797697d9`.

## Changes

Build's narrow portrait layout now uses compact illustrated rows that keep each card's name, rank, tactical role, action-key binding, supplied facts and 44-pixel Inspect/drag controls together. Unit squad size and deployment costs stay visible; bow cards retain their existing reload/delivery facts. Catalog artwork and layout are unchanged.

Inventory owns one collection scroller, with search, card rows and pagination in ordinary flow. The placement/castle pane remains independent. Narrow screens use one card column; larger portrait widths may fit two columns with a 260-pixel minimum. Existing drag-scroll registration, callbacks and search/page reset behavior remain in place.

The related short-landscape header correction reserves 180 pixels for the return action, including the longer guided-practice label, and lets read-only resource facts wrap instead of ellipsizing. It addresses the previous 4.7-pixel resource/Back bounding-box overlap qualification, subject to native rechecking.

Only game-shell CSS and build/progress metadata change in the runtime. All 40 engine modules, combat/save rules, ownership, costs and artwork are unchanged. No new Army/Muster variant or backend changes are included.

## Verification and limits

The exact canonical aggregate gate passed 2,241 engine, UI and recruitment checks with zero failures, cancellations or skips. The portable mirror adds eight existing server/packaging checks for an expected 2,249 and preserves all 188 runtime files byte-for-byte.

Seven new source/actual-UI cases cover scope, compact row content, 44-pixel controls, header reservation, 360/412-pixel search/page/inspection behavior and rotation preserving pane identities and selection. Prior source-cascade checks are narrowly updated for the intentional move from inner-card to whole-inventory scrolling; the independent placement contract remains. These checks do not establish native painting or physical touch behavior.

CI repeats the portable aggregate gate, builds the production Docker/Nginx image, checks HTTP routing/MIME/cache/404 behavior and compares every served runtime file byte-for-byte.

Native acceptance must verify complete bow and troop cards at 360x640 and 412x780, all real facts and 44-pixel actions, search/refine/paging, independent castle details, mouse/keyboard placement, rotation and restored state. Recheck 740x320 and 915x360 with safe insets and the longest current guided-practice return label; desktop and Catalog retain their established layout.

Candidate publication is not native acceptance. Physical Android/touch/lifecycle, GPU-presented FPS, end-to-end latency, extended-session stability and broad non-Auto human difficulty remain unverified. Separate dense live-HUD aim-interception warnings are outside this card-layout change. Accounts and provider/backend operation remain disabled and unverified.
