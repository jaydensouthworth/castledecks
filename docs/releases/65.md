# Release 65 candidate

This is a narrow preparation and feedback correction to the live Armory trials in release 64. Native acceptance of the correction is pending. [Release 63](https://github.com/jaydensouthworth/castledecks/commit/046526942a8b8e15e8d9d3618c166ec1a6a660f2) remains the known-good rollback.

## Changes

- Let authored trial actors wait until the first actual selected-contract unit spawns. Reading before deployment no longer lets the trial's enemies rush the flag. The trial explicitly describes this preparation assistance.
- Keep the existing recruitment queue and its timer phase, costs, reserve, cooldown, Basic Arrow and effects active. The original actor step functions resume permanently on the first spawn; recruit death cannot rearm preparation. Reset creates a fresh fixture.
- Allow actual Basic Arrow damage to a waiting target without crediting it as recruit damage or inventing a replacement target.
- Make portrait and Pause labels describe the stopped reinforcement stream instead of the suspended director's old reserve count. Name the selected contract in the Pause title; ordinary campaign/Skirmish wording remains unchanged.

Every engine file is byte-for-byte unchanged. The disposable practice fixtures, ordinary combat values and origin-state restoration are retained. Preparation assistance is explicit and is not evidence of ordinary combat balance.

## Verification and native status

The final aligned source passed 1,702 combined engine, UI and recruitment checks with zero failures or skips. The public mirror preserves all 159 runtime files byte-for-byte and adds eight portable server/packaging checks, producing a full gate of 1,710 checks.

New preparation tests cover all 12 roles after 20- and 60-second reading delays, seeded post-deployment parity, the ordinary queue phase/cooldown path, pause, duplicate-order rejection, corpse cleanup, death without rearming, Reset, and actual portrait/Pause/Return feedback. The existing trial tests continue to cover ordinary recruitment, real healing/siege damage and restoration of the original card, cart, wishlist, profile and battle.

Native release-64 testing had already demonstrated real Priest healing, Trebuchet damage and normal costs, and exact return to the original cart/wishlist. It also exposed the stale counter and pre-deployment flag-rush issues addressed here. This candidate still requires its own native delayed-deployment and corrected-feedback checks; automated tests do not establish that acceptance.

GitHub CI repeats source validation and all portable tests from pinned dependencies, then builds the actual Docker/Nginx image and checks configuration syntax, real HTTP routes, exact served source bytes, module MIME, cache headers and missing-file responses.

Release 63 remains native-accepted. Physical Android/touch, orientation/lifecycle behavior, extended browser stability, native portable save-file round trips, broad balance and exact original Flash runtime equivalence remain unverified. Existing HUD coverage and browser-local save limitations still apply. Export saves before changing website address or clearing site data.
