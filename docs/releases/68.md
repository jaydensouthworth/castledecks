# Release 68 candidate

This candidate corrects temporary-session Return presentation and makes synthetic-field transfer restrictions visible. Native acceptance is pending. [Release 66](https://github.com/jaydensouthworth/castledecks/commit/91b7e4ceaf70cf38322c677482b8c6f8b5e17bc8) remains the accepted rollback.

## Changes

Native testing of release 67 found that returning from the synthetic field restored the actual battle and profile but could leave its visible Pause identity behind. Contract trials entered from Playground shared this presentation edge case.

Temporary sessions now snapshot and restore the exact labels, hidden state, banner accessibility/objective metadata and disabled controls immediately. Return works before any render callback as well as after combat, Reset and repeated sessions. Normal and guided session control locks are restored exactly.

The synthetic field visibly disables profile/save/load entry and explains that settings and supplies are temporary, exports require Return and zero reserve prevents replacement. Existing transfer guards remain in place. Combat simulation, ordinary troop stats/costs, earned progression, accounts and backend scope are unchanged. All 37 engine modules are byte-identical to release 67.

## Verification and limits

The exact final canonical source passed 1,883 combined engine, UI and recruitment checks, with zero failures or skips. The portable mirror adds the eight existing server/packaging checks for 1,891 total, preserving all 167 runtime files byte-for-byte.

Sixteen new regressions cover prepared/live/settled origins, repeated and Reset sessions, campaign/charter/skirmish, Battery/Levy identity and flag reminders, return before a render callback, and truthful disabled controls. GitHub CI repeats the portable gate and then builds the actual Docker/Nginx image, checking syntax, real HTTP routes, exact container-served bytes, module MIME, cache headers and missing-file responses.

Native release-67 observations established that the controlled Veteran fixture stages 48 ordinary troops plus the hero, and that the local report records actual lifecycle/count/input samples. Those cloud-browser samples were small and included a portrait frame-time spike. They are not physical Android, OS/touch/GPU latency or guaranteed FPS evidence. Whole-field overview can make individual troops hard to read.

Native levy practice also exercised ordinary paid recruitment, finite manual wave accounting, independent Frontline/Support orders, live All-ground override and capacity feedback that counts corpses. Those checks do not establish a complete natural victory, broad balance or mobile difficulty. Release 68 still requires corrected Return identity/control-lock inspection and the remaining native encounter checks before acceptance.

Physical-device touch/lifecycle behavior, extended stability, native portable save-file round trips, broad balance and exact original Flash runtime equivalence remain unverified. Browser-local saves stay tied to the website address; export a backup before changing the address or clearing site data. Full live-host asset byte equality remains unverified. Repository, CI-container and native browser checks are separate evidence.
