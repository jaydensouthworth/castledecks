## Shared management frame

Hall, Deck, Build, Army, Map, Settings, Profiles and Vault share one outer safe-area frame. Existing workspace nodes move into that frame once at startup, retaining their IDs, event handlers, game state, save state and return/disposal behavior. A final stylesheet resets former root sizes and header/navigation geometry. Hall uses the same seven workspace tabs; covered Hall content is hidden visually and from assistive technology rather than remaining a second accessible dialog behind another workspace.

The short-landscape rail is 68 pixels wide with 44-pixel targets. Army resources and Map overview/region controls move into their content stage. Secondary inspectors and internal scrollers retain their own density. Card rows stretch consistently while preserving long names, costs and ownership facts. Return labels consistently name Hall.

## Optional cloud-save presentation

On a separately enabled host, opening Saves discovers account status using read-only requests. An explicit Google sign-in gesture reserves a detached-opener popup before awaiting its approved URL. Returning focus or observing the popup close triggers a bounded status check. The timer only observes popup closure; it does not repeatedly poll the account endpoint. If the popup is blocked, an explicit fallback link remains available. Guest and local play remain supported.

Three named slot cards distinguish saved, empty and unchecked metadata. Explicit upload review separates the captured local content from the remote copy being replaced. Restore retains the existing staged campaign/deck import, or explicitly confirms Wayfarer session replacement. Existing account identity, revision, CSRF, pending-upload journal, stale-response and newer-local-import protections remain. Nothing uploads, imports or migrates automatically. An enabled but unavailable service provides an honest retry with local play still available.

The static repository carries no enabled account runtime flag and no backend implementation. Backend protocol and deployment configuration are unchanged by this snapshot. Publishing frontend main does not update a separately deployed backend staging branch. Backend operational acceptance, real-provider sign-in and real cloud-slot transfer are separate from these source and harness checks.
