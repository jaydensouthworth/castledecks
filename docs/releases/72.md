# Release 72 candidate

This is a narrow correction to [release 71](71.md). Native inspection found that expanded Castle/Heraldry controls inherited an older portrait overflow rule and could escape their intended scroll pane. Candidate 71 was not accepted. Native rechecking of this correction is pending; [accepted release 70](https://github.com/jaydensouthworth/castledecks/commit/1b2f2e40c0675c76f7d29f223ab57c353ce6283c) remains the rollback. Source revision: `979a33fae2af52f348465175632364dd4f0de30f`.

## Changes

- Portrait Build's expanded castle/help section retains a bounded, independent placement scroll pane. Inventory/card scrolling remains separate; the correction outranks the legacy overflow selectors only inside the fixed portrait grid. Existing 44-pixel controls and short-landscape card deployment facts remain intact.
- Equipping rerenders the castle choices and restores keyboard focus to the live, enabled Find castles control using preventScroll, preserving both pane offsets and the same prepared keep.
- Saved-deck introduction and Apply text explicitly include all three bars, the companion and the castle. The action wraps within narrow screens and retains its 44-pixel minimum height. Saving/importing still neither equips nor grants ownership or progress.
- Optional battle reports recognize both Highwatch keep types through an explicit allowlist. Unknown input remains bounded and untrusted details are not copied into the report.

No engine mechanics, prices, save schemas, independent codec fixtures or artwork change from 71. Its castle, heraldry and optional SK2 feature boundaries remain in force. Accounts remain disabled and unconfigured.

## Verification and limits

The exact canonical source passed 2,122 engine, UI and recruitment checks with zero failures, cancellations or skips. The portable mirror adds eight existing server/packaging checks for an expected 2,130 and preserves all 185 runtime files byte-for-byte. Ten new tests cover bounded source-cascade precedence, pane/focus preservation, deck wording/wrapping and report types. The cascade helper is deliberately scoped and is not a browser layout engine.

CI repeats the portable gate and builds the real Docker/Nginx image, checks configuration, routes, MIME/cache/404 behavior and compares all runtime files over HTTP. This does not establish live-host byte equality.

Native 71 journeys verified castle purchase/equip, old/new save behavior, palette changes and an actual optional Highwatch practice victory, but the portrait defect prevented acceptance. Native 72 must separately verify expanded portrait scrolling, live focus after Equip, saved-deck action wrapping and report types. Physical touch/lifecycle, displayed FPS, GPU latency, extended sessions, enabled accounts/provider operation and broad human balance remain unverified. Preserve browser-local backup/export boundaries.
